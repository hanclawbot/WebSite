# 國小教學小遊戲（單檔 HTML）

把課程內容變成學生願意一玩再玩的小遊戲。重點不是做大型遊戲，而是：**一個清楚的學習目標、
一個簡單的動作、立刻又可愛的回饋**。所有遊戲都是單一 `.html` 檔，放進 `Htmls/` 就能用。

> 本技能的遊戲設計原則改寫自 [awesome-gamedev-agent-skills](https://github.com/gamedev-skills/awesome-gamedev-agent-skills)
> （Apache-2.0）的 game-feel、input-systems、game-ui-ux、save-systems、puzzle、prototype-fast，
> 並改成瀏覽器 JavaScript 與國小教學情境。詳見 `NOTICE.md`。

## 何時使用

- 老師要把一個單元、一組題目、一份字卡做成遊戲。
- 要修改或除錯 `Htmls/` 底下既有的遊戲網頁。
- 要替互動學習網的單元加一個複習遊戲（此時遊戲仍是獨立 `.html`，不要改動
  `Htmls/互動學習網/assets/` 的共用引擎）。

**不適用**：大型 3D 遊戲、需要伺服器或帳號的多人連線遊戲、Unity/Godot 等引擎專案。

## 必守規則（本儲存庫）

1. `<head>` 中緊接 `<meta charset="UTF-8">` 之後加 `<meta name="robots" content="noindex, nofollow">`。
2. **不寫入學生個資**（真實姓名、學號、成績、照片），範例用「王小明」「113001」這類假資料。
   排行榜只存在本機瀏覽器，不上傳。
3. **不放 API 金鑰、密碼、私人雲端連結**。
4. 不放有版權的課本圖片或遊戲素材：用 emoji、CSS、SVG、Canvas 自行繪製；音效用 WebAudio 合成。
5. 外部資源只用 Google Fonts（字型）。不要引入遊戲引擎 CDN，除非老師明確要求。
6. 新網頁要在根目錄 `index.html` 手動加一張卡片，並把「網頁數量」加 1（照現有卡片格式）。
7. 手機寬 390px 不可出現水平捲動。

## 製作流程

1. **確認一個學習目標**：用一句話寫下「玩完後學生會……」。兩個目標就做兩個遊戲。
2. **挑遊戲類型**：依內容性質選一種（見 `references/game-types.md` 的對照表）。
   - 是非、選擇 → 答題闖關／打地鼠
   - 名詞 ↔ 解釋 → 配對連線／記憶翻牌
   - 分兩類以上 → 拖曳分類
   - 步驟、時間先後 → 排序
3. **先把題庫寫成資料**：題目放在檔案最上方的陣列，與程式邏輯分開，老師之後只改這一段。
4. **從範本開始**：複製 `assets/starter.html`（答題闖關，已含計分、連擊、倒數、音效、彩帶、
   最高紀錄、減少動態選項），再依類型改寫遊戲畫面。
5. **加回饋特效**：照「回饋分級」只放該放的，不要每個動作都大爆炸（見下方）。
6. **測試**（見「完成前檢查」），再 commit、push。

## 設計原則

### 學生視角

- **三秒看懂怎麼玩**：開始畫面一句玩法說明＋一個大按鈕。不要長篇規則。
- **一次只教一件事**：關卡由易到難，新機制先單獨出現一次再混合。
- **錯了也要學到東西**：答錯時顯示正確答案與「為什麼」，不要只顯示 ❌。
- **鼓勵而非懲罰**：用「再想想看！」「再接再厲！」；不扣到負分；不做羞辱性的失敗畫面。
- **一局 2～5 分鐘**：題數 5～10 題，可以馬上「再玩一次」。題目與選項每局打散。
- **公平**：計時要寬鬆（低年級 20 秒以上），切換分頁時暫停倒數；不要求同時按兩個鍵。

### 回饋分級（game feel）

一個好的回饋是好幾個小反應同時發生（約 0.1 秒內），而且**短暫、會回到原狀**。

| 等級 | 時機 | 回饋 |
|---|---|---|
| 小 | 點擊、翻牌、拖起 | 按鈕下壓、輕微縮放 |
| 中 | 答對一題、配對成功 | 叮咚音效＋彈跳（overshoot）＋少量彩帶＋分數跳動 |
| 大 | 過關、全對、新紀錄 | 上行音階＋大量彩帶＋星星 |
| 錯誤 | 答錯 | 低音＋左右輕晃＋標出正確答案（不要劇烈震動畫面） |

- 動畫用有彈性的 easing（`cubic-bezier(.34,1.56,.64,1)`），不要線性。
- 特效只動「畫面」，不要卡住遊戲邏輯；回饋期間鎖住重複點擊。
- 提供「音效開關」與「減少動態效果」，並尊重 `prefers-reduced-motion`。

### 介面

- 觸控目標至少 **48×48px**（範本按鈕 56～64px），字級至少 18px，題目 22px 以上。
- 用 Flex／Grid 排版，不用絕對座標；手機時選項改成單欄。
- 畫面用「開始 → 遊戲 → 結果」三個 `section` 切換，不要一堆布林旗標。
- HUD（題號、分數、時間）在事件發生時更新，不要每幀重畫 DOM。
- 按鈕要能用鍵盤操作（用 `<button>`，保留 `:focus-visible` 外框）。

## 技術模式（摘要）

完整程式碼在 `references/patterns.md`：

1. **輸入用 Pointer Events**：`pointerdown/move/up` 一套程式同時支援滑鼠、觸控、觸控筆；
   拖曳時 `setPointerCapture`，元素加 `touch-action: none` 避免頁面跟著捲動。
2. **遊戲迴圈用 `requestAnimationFrame` + dt**：移動量乘上經過秒數，並把 dt 上限設 0.05 秒，
   避免切分頁回來時物件瞬移。沒有動畫時停止迴圈。
3. **狀態是唯一真相**：先改 `state`，再由 `render()` 畫出來；動畫中鎖住輸入。
4. **打散要正確**：Fisher–Yates；打散選項時同步更新答案索引。
5. **本機紀錄**：`localStorage` 存 `{version, best, ...}`，讀寫都包 `try/catch`，讀不到就用預設值。
   只存純資料，不存 HTML 或程式碼。
6. **音效**：WebAudio 振盪器合成短音；第一次使用者點擊後才建立 `AudioContext`（瀏覽器規定）。
7. **Canvas 高解析**：依 `devicePixelRatio`（上限 2）設定畫布尺寸，再 `setTransform` 縮放。

## 常見錯誤

- 用 `click` 做拖曳、或只綁 `mousedown` → 平板不能玩。改用 Pointer Events。
- 連點同一個正確答案重複加分 → 作答後立即 `locked = true` 並停用按鈕。
- 正確答案永遠在第一個 → 每局打散選項。
- 計時器沒清掉，進入下一題後兩個 `setInterval` 同時跑 → 開新計時前先 `clearInterval`。
- `localStorage` 在私密模式丟例外導致整個遊戲白屏 → 一律 `try/catch`。
- 用 `innerHTML` 塞入題目文字 → 題目含 `<` 會壞版；一般文字用 `textContent`。
- 畫面寬度用固定 px → 手機出現水平捲動。
- 特效過量（每次點擊都震動畫面）→ 學生頭暈、真正的過關反而不明顯。

## 完成前檢查

1. 用 Playwright（`executablePath: '/opt/pw-browsers/chromium'`）在 1280px 與 390px 開啟：
   - 沒有 JavaScript 錯誤（Google Fonts 失敗可忽略）
   - `document.documentElement.scrollWidth <= innerWidth`（沒有水平捲動）
2. 自動玩完一局：點開始 → 每題點一個選項 → 下一題 → 結果畫面出現，分數與星星正確。
3. 截圖檢查三個畫面（開始、遊戲中、結果），文字沒有重疊或超出卡片。
4. 用 Node 核對題庫：每題 `ans` 在選項範圍內、沒有重複題目。
5. 確認 robots noindex、沒有個資與金鑰，根目錄 `index.html` 已加卡片。

測試腳本範例在 `references/patterns.md` 最後一節。
